# Windows code signing

Installers built on a local machine are **unsigned**. Windows SmartScreen will
usually warn that the app is not trusted, and Windows 11 with Smart App Control
enabled can block it entirely. Signing the installer with an Authenticode
code-signing certificate removes the "unsigned publisher" part of that warning.

> A certificate cannot be generated by this project. You must buy or otherwise
> obtain an OV or EV **code signing** certificate from a Microsoft-trusted
> provider. SSL certificates do not work. Even with a fresh certificate,
> SmartScreen can still show a warning until the file and signing certificate
> build reputation with Microsoft; signing every release with the same
> certificate carries that reputation forward. You can also submit the signed
> file to [Microsoft's file submission service](https://www.microsoft.com/en-us/wdsi/filesubmission/).

## One-time setup

1. Get a code signing certificate as a `.pfx` file (a `.cer` plus its private
   key can be converted with
   `openssl pkcs12 -export -in cert.cer -inkey private-key.key -out certificate.pfx`).
2. Base64-encode the `.pfx`:
   `certutil -encode certificate.pfx certificate-base64.txt`
3. In the GitHub repository, open **Settings → Secrets and variables → Actions**
   and add:

   | Name | Value |
   | --- | --- |
   | `WINDOWS_CERTIFICATE` | Contents of `certificate-base64.txt` |
   | `WINDOWS_CERTIFICATE_PASSWORD` | The `.pfx` export password |

4. Optional: add a repository **variable** `WINDOWS_CERTIFICATE_TIMESTAMP_URL`
   if your provider requires a specific RFC 3161 timestamp server. The workflow
   defaults to `http://timestamp.digicert.com`.

Never commit the `.pfx`, its password, or the decoded base64 to the repository.

## Producing a signed installer

The [`sign-windows`](../.github/workflows/sign-windows.yml) workflow is manual:

1. Open **Actions → Build signed Windows installer → Run workflow**.
2. To replace an existing release's installer, enter its tag (for example
   `v1.2.0`) and leave **Replace the installer asset on that release** checked.
3. The workflow imports the certificate, sets Tauri's
   `bundle.windows.certificateThumbprint` from the imported certificate,
   builds with `npm run tauri build`, verifies the Authenticode signature, and
   uploads the installer with the `Windows x64 installer` label.

Leave the tag blank to build and verify a signed installer without publishing
it. The workflow fails early with a clear message if the secrets are missing.

## Releases before signing was configured

Versions up to and including 1.2.0 were built locally and are unsigned; their
release notes say so. Re-running the workflow with a tag replaces the unsigned
asset with a signed one built from that tag.
